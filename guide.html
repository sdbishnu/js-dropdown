BSelect Guide

Quick start

BSelect is a custom dropdown written in plain JavaScript (no framework, no jQuery needed) with an AngularJS 1.x wrapper. One component for single and multiple select, local or server data, search, lazy loading, themes and a built-in settings panel.

Install (two tags)

<script src="dist/bselect.bundle.min.js"></script>   <!-- loads dist/bselect.min.css by itself -->
<!-- AngularJS pages add the wrapper after it: -->
<script src="ng/bselect.ng.js"></script>   <!-- angular.module('app', ['bselect']) -->

Use it

// plain JS, on an id
var ward = bselect('#ward', { options: wards, placeholder: 'Select ward' });
var user = bselect('#user', { url: 'php/user.php?action=dropdown', multiple: true });
ward.getValue();  ward.setValue(5);  ward.clear();  ward.reload();  ward.destroy();

<!-- plain HTML, no JS -->
<select id="empid3" name="emp[3]" data-bselect data-options="staff" data-value="5"></select>

<!-- AngularJS -->
<bselect ng-model="f.user" url="php/user.php?action=dropdown" multiple on-change="changed($value, $items)"></bselect>

A <select> or <input> target keeps its native value in sync, so normal form submits work. Every option can also be a data-* attribute (data-load="scroll" data-size="lg").

Try it here – open the dropdown and click the gear to explore the settings:

Forms and loops with many dropdowns

bselect.data('staff', staffArray);                 // name a big array once (shared, indexed, built once)
bselect.many('.js-staff', { options: 'staff' });   // build a whole loop in one call

120 dropdowns on a 2000-item array build in about 30 ms.

Data and loading

OptionWhat it does
optionsArray (of values, or objects), a name registered with bselect.data(), or a function.
url + params + method + headersLoad from your API. GET sends a query string, POST a form body.
handler(params, state)Your own loader (returns rows or a promise). state has page, pageSize, search, sortDirection.
valueField / labelFieldWhich item fields are the value and the text (defaults id and name).
transform, itemsField, totalField, hasMoreFieldUnderstand any response shape.
resolve / resolveUrlGet the labels of saved ids that are not loaded yet.

Loading modes option: load

ValueBehaviour
'scroll' (default)Lazy load: the first pageSize rows (20), then more as you scroll, with the "Scroll to continue" strip. Safe for endpoints that ignore paging.
'all'Everything at once; local lists are still drawn in slices.
'button'A "Show more results" button loads the next page.

loadOn: 'open' (default) or 'init'. pageSize is the rows added each time.

Speed on long lists

  • Virtual scrolling (virtual: 'auto', virtualFrom: 150): only the rows in view are drawn, so 5,000 rows cost about 20 DOM rows.
  • Shared option cache: an array is prepared once for every dropdown that uses it.
  • Request cache (cache: 30000 ms): the same url + params is not asked twice. bselect.clearCache() / inst.reload() always ask again.
  • Preload (preload: true): server lists start loading when the pointer reaches the button or it gets focus, so opening does not wait.
  • One document click listener, delegated row events, the panel DOM is released on close.

Selecting

Single and multiple multiple

Single select shows radio rows; multiple shows checkboxes, min / max, chips (display: 'chips', maxChips) and the tabs below.

All / Selected tabs viewTabs · selectAll

TabShowsAction on the right
AllThe full list (search, lazy load, virtual scroll as usual).Select all / Unselect all (the rows listed, honours max)
Selected (n)Only the chosen rows; unticking a row removes it from the tab.Clear all

Single select has no tabs. viewTabs: false turns them off; selectAll: false hides Select all.

Apply / Cancel commit · commitClose

With commit: true (multiple select) edits stay pending: the model and the change event update only when you press Apply. Cancel (or closing, by default) discards them. commitClose: 'apply' makes closing apply. Events: apply, cancel.

Recent and favourites recent · favorites

recent: 5 lists the last 5 picks first; favorites: true adds a star to each row and lists starred items first. Both are remembered in the browser (localStorage).

Validation, cascade, create

  • required, min, max with messages; validate(), isValid().
  • dependsOn (+ dependsParam): the child is disabled until the parent has a value, reloads when it changes and clears its own value.
  • creatable: true: typing a new text offers "Create ...".

Search and sort

  • Multi-word search ("john card" needs both words), the matched words are highlighted (highlight). Sub text is searched together with the label.
  • searchMode / serverSearch: Auto asks the server only while rows are missing; Browser filters loaded rows; Server always sends search. searchMinChars waits for N letters.
  • The sort button sorts in natural order (Item 2 before Item 10, case and accents ignored). sortBy picks the field, serverSort sends the direction to your API.
  • Keyboard: arrows, Home / End, PageUp / PageDown, type-ahead, Enter, Esc, Tab.

Rows, pictures and groups

Pictures and sub text come from your data. Put the values in the array / API rows and point the option at the field. The per-option editors in the settings gear are only for trying things out.

Groups and custom rows

groupField: 'dept' shows a header per group (keep your data ordered by group). renderItem(item) returns your own row text or element. checkStyle is the row indicator: 'box' (default), 'tick' or 'none'.

Count line

Separate design for the button and the dropdown

bselect('#ward', {
  field: { shape: 'pill', size: 'lg' },          // the closed button
  panel: { mode: 'dark', shape: 'square' }       // the open dropdown
});

The search box, sort button and settings gear always share one shape and height: they follow the dropdown's shape / radius and size, also when changed live in the gear.

CSS variables

.my-form .bselect { --bselect-color: #0f766e; --bselect-radius: 12px; }

Configure once, override anywhere

Order (a later layer wins): built-in default → global → per dropdown → own options.

bselect.defaults({ color: '#0f766e', size: 'sm' });                          // global
bselect.defaults('#ward', { field: { shape: 'pill' }, panel: { mode: 'dark' } }); // one dropdown, set from any js file
bselect('#ward', { size: 'md' });                                             // own wins

Themes and presets: bselect.theme('hospital', {...}), bselect.preset('wards', { url: '...', theme: 'hospital' }), then bselect('#x', { preset: 'wards' }).

The settings gear has an Export tab that writes your changes in exactly this format (global, per dropdown, JSON or data-*). Try things in the gear, copy, paste into your code.

The settings gear

The gear inside the dropdown is a test bench and code generator: change any option, watch the dropdown react, then copy the result from the Export tab. It is on by default; with it off (settingsButton: false) nothing of it is rendered at all. With it on, the popup is built when the gear is clicked and the heavy per-option editors only when their tab is first opened. Use Find to search all settings; Guide opens this page.

AngularJS 1.x wrapper

<bselect ng-model="f.user" preset="users"></bselect>
<bselect ng-model="f.users" url="php/user.php?action=dropdown" load="scroll" multiple display="chips"
         placeholder="Pick users" params="{active:1}" on-change="changed($value, $items)"></bselect>
<bselect ng-model="f.ward" options="wardList" ng-disabled="locked" ng-required="true"></bselect>
<bselect ng-model="f.ward" url="php/ward.php" depends-on="f.dept" depends-param="dept_id"></bselect>
  • Any option works as a kebab-case attribute; options, params, depends-on, on-change, config are Angular expressions.
  • model-type="object" puts the item object(s) in ng-model; ng-required, ng-disabled, ng-change and form validity work.
  • Cheap watchers for ng-repeat forms (90 dropdowns settle in about 70 ms).
  • The old API still works: bselect.bind, server / local, refresh, toParam, grouped config="...".
